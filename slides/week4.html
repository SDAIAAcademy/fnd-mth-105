Block A · induction

Induction proves a claim for every n with two finite pieces of work

Baseshow P(1), or P of the first value
→
Hypothesisassume P(k) for one k ≥ 1
→
Stepshow P(k + 1), using P(k)
  • Base and step together reach every n: P(1), so P(2), so P(3), and so on
  • Without the base, the step proves nothing; without the step, the base proves one case

The dominoes picture works: the step says each domino knocks the next, the base pushes the first. Insist that the hypothesis is assumed for one k, not for all n, which would assume what is to be proved.

Worked example

Test it, then prove it: 1 + 2 + … + n = n(n + 1) / 2

all(sum(range(1, n + 1)) == n * (n + 1) // 2
    for n in range(1, 5001))   # True
  1. Base. n = 1: 1 = 1 · 2 / 2
  2. Hypothesis. 1 + … + k = k(k + 1) / 2
  3. Step. 1 + … + k + (k + 1) = k(k + 1) / 2 + (k + 1) = (k + 1)(k + 2) / 2, using the hypothesis for the first k terms ∎

A parallel to the lab's first claim, with different numbers. Point at where the hypothesis is used: the rubric looks for that sentence. Then ask what the test of 5,000 cases added: confidence before the effort of proof, and a check on the formula's exact form (n(n + 1)/2, not n²/2).

Strong induction

Strong induction may assume the claim for every value below k + 1

Claim. Every integer n ≥ 2 is a product of primes.

  • If n is prime, it is a product of one prime
  • Otherwise n = a · b with 2 ≤ a, b < n
  • By the hypothesis for a and for b, both are products of primes, so n is too ∎

When to use it

When the step needs a smaller case that is not k itself: a factor, half of n, a subtree. Recursive code that splits its input is proved this way.

The hypothesis here is "the claim holds for every m with 2 ≤ m ≤ k". The base is hidden in the first bullet: a prime needs no smaller case. PS7's staircase bound uses strong induction.

Checkpoint

What is missing?

A proof that "n + 1 < n for every n ≥ 1" assumes k + 1 < k and adds 1 to both sides to get k + 2 < k + 1. What is wrong with it?

It has no base case, and the base case is false
Adding 1 to both sides is not allowed
The hypothesis assumes what it wants to prove
It needs strong induction instead
Why. The step is valid on its own; with no true starting case it proves nothing. For n = 1, 2 < 1 is false.

Answer A. A valid step from a false start is the classic way a "proof" of a false claim looks complete.

Block B · structural induction

Structural induction follows the way a structure is built

A recursive definition

A nested list is either a number, or a list of nested lists. A tree is a node with a list of subtrees.

Its induction

Prove the claim for the smallest pieces, then show that building from pieces that satisfy it gives a whole that satisfies it.

No n needed. The induction is on the structure itself; each recursive call works on a smaller part.

Ask the room to write the recursive definition of a list (empty, or an element followed by a list): ordinary induction on n is structural induction on that definition.

Worked example

In a tree where every node has 0 or 2 children, leaves = inner nodes + 1

  • Base. A single node: 1 leaf, 0 inner nodes
  • Step. A root with subtrees L and R that satisfy it: leaves = (inner(L) + 1) + (inner(R) + 1) = (inner(L) + inner(R) + 1) + 1
  • The root is the one new inner node, so leaves = inner + 1 ∎
def leaves(t):
    if not t["children"]:
        return 1
    return sum(leaves(c) for c in t["children"])

A parallel to the lab's tree claim, which is about edges and nodes in any tree. Test first: generate random trees whose nodes have 0 or 2 children and compare the counts. The proof's two cases are the two branches of the recursive function.

Recursive code

A recursive function is proved correct by induction on the size of its input

def total(xs):
    if not xs:
        return 0
    return xs[0] + total(xs[1:])
  1. Base. The empty list returns 0, its sum
  2. Hypothesis. total is right on lists of length k
  3. Step. On length k + 1 it returns xs[0] plus the sum of the rest, by the hypothesis: the sum ∎

Ask what else must hold: termination, since each call is on a shorter list. A recursive call on a list that does not shrink is where such proofs, and programs, fail.

Checkpoint

What may the step assume?

To prove by structural induction that a recursive depth function on nested lists is correct, the step for a list [a, b, c] may assume:

that the function is correct on [a, b, c]
that it is correct on a only
that it is correct on each of a, b and c
that it is correct on every list of length 2
Why. The hypothesis is the claim for every immediate part of the structure; the step builds the whole from them.

Answer C. D is not wrong as a fact but is the wrong hypothesis: a, b and c may be nested lists of any length.

Block C · loop invariants

An invariant is true before the loop and after every pass

total, i = 0, 0
while i < len(xs):
    # invariant: total == sum(xs[:i])
    total += xs[i]
    i += 1
PartShow
Initialisationtrue before the first pass
Maintenancea pass keeps it true
Terminationthe loop stops
At exitinvariant and exit condition give the result

Here: initially total = 0 = sum of no elements; a pass adds xs[i] and moves i on; i grows to len(xs); at exit i = len(xs) and total is the whole sum. It is induction on the number of passes. In code, write the invariant as an assert while testing.

Using tests well

Generated tests find counterexamples cheaply, so run them before you prove

Many cases

Every n up to a bound, or random inputs. Cheap evidence and a fast way to find a false claim.

Edge cases

Zero, one, the empty list, equal values, the first case where a pattern could change.

Their limit

Write what the tests cover: "n from 1 to 1,000, no counterexample". Never write "true".

The portfolio rubric gives 20 points to test code before each proof, including "an honest note of what the tests cannot show". That note is the third card.

Checkpoint

Which statement is an invariant?

A loop counts the even numbers in a list: count starts at 0, i at 0; each pass adds 1 to count if xs[i] is even, then adds 1 to i. Which invariant proves it correct?

count ≥ 0
count equals the number of evens in the whole list
count = i
count equals the number of evens in xs[:i]
Why. It holds at the start (0 evens in an empty prefix), each pass keeps it, and at exit i = len(xs) gives the result.

Answer D. B is the goal, not an invariant; A is an invariant too weak to prove anything.

Week 4 · wrap-up

Three things to keep

Base, hypothesis, step

Say where the step uses the hypothesis. A step alone proves nothing.

Induction follows structure

Integers, lists, trees and loops: the proof follows the way the thing is built.

Tests refute, proofs confirm

Write what your tests cover, never "true", until the proof exists.
