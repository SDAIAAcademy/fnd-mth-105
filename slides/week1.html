Block A · sets

A set has no order and no repeats, and a table of distinct rows is one

  • {2, 3, 5} = {5, 3, 2} = {2, 2, 3, 5}: order and repeats do not count
  • x ∈ A reads "x is a member of A"; A ⊆ B, every member of A is in B
  • A row of a table is a tuple: (T3, room 2) is not (room 2, T3)
  • A table with no duplicate rows is a set of tuples
A = {2, 3, 5}
B = {5, 7}
A | B, A & B, A - B
# {2, 3, 5, 7}, {5}, {2, 3}

Ask: is a list a set? No: [2, 2, 3] has a repeat and an order. Python's set drops both, which is why the lab counts with sets on purpose and notices when a database does not.

Operations

Union, intersection and difference answer the coordinator's first questions

QuestionOperationExample: X = {a, b, c}, Y = {b, d}
Worked at either siteX ∪ Y{a, b, c, d}
Worked at bothX ∩ Y{b}
Only at the firstX − Y{a, c}
How many at either|X ∪ Y| = |X| + |Y| − |X ∩ Y|3 + 2 − 1 = 4

The last line is inclusion-exclusion for two sets. Week 6 uses it on a whole register.

Test before prove, the first time: generate random sets in code and check the last line on a thousand pairs. Then the proof: every element of X ∩ Y is counted twice in |X| + |Y|, once too often, and every other element of the union once.

Products

A Cartesian product holds every pair, and its size is the product of the sizes

{T1, T2} × {room 1, room 2, room 3} =

{(T1, room 1), (T1, room 2), (T1, room 3), (T2, room 1), (T2, room 2), (T2, room 3)}

|A × B| = |A| · |B| = 2 · 3 = 6

A relation is a subset of a product

Any set of pairs from A × B is a relation from A to B. With 6 pairs there are 2⁶ = 64 relations, from the empty one to all of A × B.

Here T1 and T2 are training modules and the rooms are a parallel example, not the lab's tables. The count of relations previews week 5: each pair is in or out, two choices six times.

A training team lists 8 modules and 5 rooms. It wants one row for every module and room that could be booked together. How many rows does that table have?

Why. The table is the product of the two sets: 8 · 5 = 40 pairs.

Block B · functions

A function gives every input exactly one output

A function from X to Y

A relation in which each x in X appears in exactly one pair. X is the domain, Y the codomain.

Two ways to fail

Some x has no output (the map is partial), or some x has two outputs (the map is not single-valued).

ModuleRoomVerdict
T1room 1fine
T2room 1, room 3two outputs: not a function
T3(none)no output: partial

In data, "is this column a function of that one?" is a question you ask before every lookup: if a key maps to two values, a lookup silently picks one.

Three properties

Injective, surjective and bijective say how outputs are shared and covered

Injective

No two inputs share an output. Test: f(x) = f(x′) forces x = x′.

Surjective

Every element of the codomain is reached by some input.

Bijective

Both: a perfect pairing, so the map has an inverse.

On the integers. n ↦ 3n is injective and not surjective (5 is never reached); n ↦ n − 7 is a bijection.

Prove the first claim on the board: 3m = 3n gives m = n, so injective; 5 = 3n has no integer solution, so not surjective. This is the first direct proof and the first counterexample of the course.

In data work

Each property is a promise a system relies on

PropertyWhere a system relies on it
Function (total)Every record finds its value in a lookup
InjectiveA key or a code identifies one record: no two people check in as one
SurjectiveEvery category is used: every event has staff
BijectiveA code can be swapped back for the record: pseudonymisation, week 6

Link forward: in week 5 short check-in codes stop being injective as the centre grows; in week 6 a bijective code still leaves people findable, because other columns identify them.

Checkpoint

What kind of map is this?

A sports hall gives each of its 120 lockers to one of 4 cleaning rounds, every round gets 30 lockers. As a map from lockers to rounds, which is true?

A bijection, since every round gets the same number
Not a function, since each round has many lockers
Injective, since every round is used
A surjective function that is not injective
Why. Each locker has exactly one round (a function), every round is reached (surjective), and 30 lockers share each round (not injective).

Answer D. Draw the arrows: many arrows land on each round, one arrow leaves each locker.

Block C · relations

Equivalences group things; orders rank them

Equivalence relation

Reflexive, symmetric and transitive. "Lives in the same district as" splits people into groups, the equivalence classes.

Partial order

Reflexive, antisymmetric and transitive. "Must be taken before, directly or through others, or is the same module as" ranks modules; some pairs are not comparable.

  • Reflexive: every x relates to itself. Symmetric: x R y gives y R x
  • Transitive: x R y and y R z give x R z. Antisymmetric: x R y and y R x give x = y

Definitions only this week; week 3 checks them in code on nine relations and proves or refutes them. Ask for an everyday relation that is symmetric but not transitive ("is a neighbour of") so the four words already have examples.

Composition

Composing two relations follows one, then the other

R: module → room(T1, r1), (T2, r1), (T3, r2)
→
S: room → building(r1, North), (r2, South), (r2, Annex)
→
R then S(T1, North), (T2, North), (T3, South), (T3, Annex)

(x, z) is in the composition when some y has (x, y) in R and (y, z) in S.

"Some y" is the first existential quantifier of the course; week 3 names it. The order of writing differs between books (S ∘ R or R ; S): say "R, then S" aloud and the notation stops mattering.

In a database

A join is a composition that keeps repeats

select r.module, s.building
from R r join S s on r.room = s.room
  • One output row per pair of matching rows
  • If T2 used room 1 twice (two bookings), (T2, North) appears twice
  • select distinct returns the composition, a set
What goes wrong. Counting join rows as "modules per building" overcounts by every repeat. The lab measures how many.

The relational model is built on sets; SQL tables are multisets (bags). The lab joins the centre's assignments with its shifts in an in-memory database and compares the row count with the composition.

Checkpoint

Join rows or composition pairs?

A library joins loans (reader, copy) with copies (copy, title). One reader borrowed two copies of the same title. Compared with the composition "reader borrowed title", the join returns:

the same number of rows as there are pairs
one fewer row, as the second copy is dropped
one more row: the (reader, title) pair appears twice
an error, as the key repeats
Why. Each loan row matches one copy row, so two loans give two rows with the same (reader, title); the composition keeps that pair once.

Answer C. Then launch the lab: the centre's version of this has several repeats.

Week 1 · wrap-up

Three things to keep

Tables are sets of tuples

Products count the possible rows; relations are subsets of them.

Functions make promises

Total, single-valued, injective, surjective: check each one; data breaks them quietly.

Joins compose relations

With repeats. Distinct pairs are the composition.

Ask each participant for one map in their own work that they assumed was injective without checking.
