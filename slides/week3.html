Valid or not?

Rule: if a meter reading is missing, the bill is estimated. This bill is not estimated. What follows?

The reading is not missing
The reading is missing
Nothing: the rule says nothing about estimated bills
The bill would be estimated if the reading were present
Why. Modus tollens: from p → q and ¬q, conclude ¬p. No row has both premises true and "missing" true.

Answer A. If many pick C, write the four rows and strike out those where a premise is false: one row remains.

Block A · quantifiers

A predicate becomes true or false once you fill its variable

  • P(x): "x is overdue", over a domain such as the loans of a library
  • ∀x P(x): every loan is overdue
  • ∃x P(x): at least one loan is overdue
  • The domain is part of the claim: change it and the truth can change
all(overdue(x) for x in loans)   # for every
any(overdue(x) for x in loans)   # there exists

On a finite table, all and any evaluate a quantifier exactly. Ask: what does all return on an empty table? True: a "for every" claim about nothing is vacuously true, like the light parcels of week 2.

Data-quality rules

A data-quality rule is a quantified statement your code can evaluate

Rule in wordsIn logic
Every loan belongs to a member∀l ∃m: holder(l, m)
No member holds more than five loans∀m: count of l with holder(l, m) ≤ 5
Every child member has a guardian on file∀m: child(m) → guardian(m)
A failed rule comes with a witness: the loan with no member, the child with no guardian. Print the witness, not only "False".

The centre's register has a rule of the third kind: every volunteer under 18 has guardian consent on file. PS3 asks for its translation; the trainer has the count of rows that break it.

Negation

Negating a quantifier swaps it and moves the "not" inside

StatementIts negation
∀x P(x): every loan is returned∃x ¬P(x): some loan is not returned
∃x P(x): some book is damaged∀x ¬P(x): no book is damaged
∀x ∃y R(x, y): every member has a card∃x ∀y ¬R(x, y): some member has no card at all
Order matters. ∀x ∃y "every member has a card" is not ∃y ∀x "one card belongs to every member".

Do the third line slowly, one quantifier at a time. Then read the order warning aloud with the room: the swap turns a normal rule into an absurd one.

Block B · relation properties

Each property of a relation is a "for every" statement

Reflexive∀x: x R xone x not related to itself

Antisymmetric∀x, y: x R y ∧ y R x → x = ytwo different elements related both ways

The last column is the negation of each statement, read off with the rule from block A. The lab writes each checker as one line of all.

Kinds of relation

The properties decide what a relation can be used for

KindPropertiesExample
Equivalencerefl, sym, transborn in the same month
Partial orderrefl, anti, transis a subset of
Strict orderirrefl, anti, transfinished earlier than
Preorderrefl, transis at least as tall as
  • Group with an equivalence
  • Rank or schedule with an order
  • A preorder ranks with ties between different elements

"At least as tall as" is not antisymmetric: two different people of the same height relate both ways. That is why it is a preorder and not a partial order. A function, from week 1, is a further property of a relation between two sets.

Testing or proving

On a finite relation, checking every case is a proof

Finite: check them all

"Same month" on 40 people: 1,600 pairs and 64,000 triples. Checking them all proves the property for those 40.

Infinite: test, then prove

"Subset of" on all sets, "divides" on all integers: no loop ends. Tests can refute; only an argument proves.

Mind the definition. If a relation is defined by a rule ("within 5 km"), a property may fail for the next element even when it holds for today's data.

Ask: if "within 5 km" happens to be transitive on today's 40 sites, is it transitive? No: a new site between two others can break it. The property belongs to the definition, not to the sample.

Block C · proofs

A direct proof goes from the hypothesis to the conclusion, one justified step at a time

Claim. The sum of two even integers is even.

  1. Let a and b be even: a = 2k and b = 2l for integers k, l (definition)
  2. a + b = 2k + 2l = 2(k + l) (algebra)
  3. k + l is an integer, so a + b is even (definition) ∎

The shape

State the claim with its domain. Unfold the definitions. Calculate. Fold back into the definition of the conclusion. Name each reason.

Before the proof, test it in code: all((a + b) % 2 == 0 for a in range(-50, 51, 2) for b in range(-50, 51, 2)). The test covers 2,601 pairs; the proof covers every pair. Write the reasons in brackets: that is what the rubric's "every step justified" means.

Refuting

One counterexample refutes a "for every" claim

ClaimCounterexample
Every prime is odd2
If a² = b² then a = b, for integersa = 3, b = −3
n² − n + 11 is prime for every n ≥ 1n = 11: 121 = 11 · 11

The last claim holds for n = 1 to 10. Code finds the counterexample in a moment; a person checking by hand may stop too early.

Run the search live: next(n for n in range(1, 100) if not isprime(n*n - n + 11)) with a small primality function. Week 4's lab has a claim of the same kind that survives forty tests.

Contradiction

A proof by contradiction assumes the opposite and reaches something impossible

Claim. If n² is even, then n is even (n an integer).

  1. Suppose n² is even and n is odd: n = 2k + 1
  2. n² = 4k² + 4k + 1 = 2(2k² + 2k) + 1, which is odd
  3. n² is both even and odd: impossible. So n is even ∎

Say what you assumed

The first line names the assumption; the last names the contradiction. A reader can then check that the assumption really is the negation of the claim.

This one is also a proof of the contrapositive (n odd → n² odd), which is often the cleaner way to write it. Point out the link to week 2: p → q and ¬q → ¬p are equivalent.

Why. The test is evidence and finds no counterexample. The proof: n² + n = n(n + 1), a product of two consecutive integers, one of them even.

Week 3 · wrap-up

Three things to keep

Negate carefully

Swap ∀ and ∃ and move the "not" inside. The negation tells you what a counterexample looks like.

Properties decide use

Group only with an equivalence; rank only with an order. Check before you use.

Finite or infinite

Every case checked is a proof for a finite set. For the integers, tests refute and proofs prove.
