Block A · graphs

A directed graph is a set of nodes and a relation on them

  • An edge (u, v) is a pair in the relation: here "u must finish before v starts"
  • In-degree: edges arriving; out-degree: edges leaving
  • A source has in-degree 0; a sink has out-degree 0
  • A path follows edges forward; a cycle is a path that returns to its start
  • A DAG is a directed graph with no cycle; a tree has no cycle even with edges read both ways

A morning of five tasks

A and B feed C; C feeds D and E. Sources A, B; sinks D, E. The in-degrees add up to 4, the number of edges.

Week 3 met relations as sets of pairs; a directed graph is the same object drawn. Trees were week 4's induction example. Leave the question of why the in-degrees always add up to the number of edges open: the lab asks it.

Why cycles matter

A cycle of dependencies means no job on it can ever start

1 · Start what is readyEvery job whose dependencies have all finished
→
2 · Peel it offRemove it; its successors lose one unfinished dependency
→
3 · Repeat or stopAll gone: no cycle. Some left, none ready: a cycle among them
Takeaway. In a graph with no cycle there is always a job with nothing unfinished before it, so peeling only stops early when a cycle exists.

Press once per step. Proof of the takeaway: if every remaining job had an unfinished predecessor, walk backwards from any job; with finitely many jobs the walk must repeat one, which is a cycle. Jobs downstream of a cycle are also left over, so the leftovers are the cycle and more. A library finds one cycle directly, for example with a function that returns its edges.

Edges: A → B, B → C, C → D, D → B, A → E. Peeling starts with every job that has no dependency. Which jobs are never ready?

Block B · topological order

A topological order puts every edge forward

The jobs in the order they are peeled form a topological order: for every edge (u, v), u comes before v.

The morning of five tasks has 4 of them: ABCDE, ABCED, BACDE, BACED. An order is rarely unique.

Order A C B D E: edgePositionsForward?
A → C1, 2yes
B → C3, 2no
C → D2, 4yes
C → E2, 5yes
Check, do not trust. The definition is edge by edge: one backward edge makes an order invalid, and no backward edge, with every node once, makes it valid.

Orders from slide_numbers.py, week 7. Check the table aloud: B → C points backwards, so A C B D E is not a running order. The library's order and the peeled order may differ and both pass. The lab writes this check as a function.

Why peeling is correct

A loop invariant proves the peeled order is topological

PartFor the invariant "every job in the list has all its predecessors earlier in the list"
InitialisationThe list is empty: nothing to check
MaintenanceA job is added only when all its predecessors are already in the list
TerminationIf every job is peeled, the invariant covers every edge: the list is a topological order

Week 4's three parts, applied to the algorithm the lab writes. Termination: each pass removes one job, so the loop ends after at most n passes. The capstone accepts an invariant proof as the induction proof.

Block C · recurrences

Count paths into a node from the counts into its predecessors

In a grid walked right or down, the paths into a point are the paths into the point above plus the paths into the point on the left: P(i, j) = P(i − 1, j) + P(i, j − 1), with 1 along the edges.

111
123
136

Why it works

Every path into a point arrives by exactly one last edge, so the paths split into disjoint groups, one per predecessor: the sum rule of week 5. Walk the points in a topological order so each sum uses finished counts.

From slide_numbers.py, week 7. The same recurrence works on any graph without a cycle; the lab applies it to the pipeline and checks it against a list of every path.

Solve, then prove

Guess a closed form from the first values, then prove it by induction

1 · RecurrenceLinks among n people: H(1) = 0, H(n) = H(n − 1) + (n − 1)
→
2 · Guess0, 1, 3, 6, 10: H(n) = n(n − 1)/2
→
3 · ProveH(n − 1) + (n − 1) = (n − 1)(n − 2)/2 + (n − 1) = n(n − 1)/2
Takeaway. The step uses the hypothesis for n − 1: that is the induction. Test the guess in code first, as the capstone asks.

The new person links with each of the n − 1 already there. Base: H(1) = 0 = 1 · 0/2. Factor (n − 1) out in the step: (n − 1)((n − 2)/2 + 1) = (n − 1) · n/2.

Week 7 · wrap-up

Three things to keep

Peel to find cycles

If jobs remain and none is ready, a cycle holds them.

Check every edge

An order is valid when every edge points forward: a finite check.

Count by recurrence

Sum over predecessors, then prove the closed form by induction.

Ask which dependency list in their own work they could check this way: build steps, approvals, course prerequisites.
